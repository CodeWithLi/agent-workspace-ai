# Agent 设计

所有 Agent 统一通过 `backend/app/core/llm.py:get_llm()` 使用 OpenAI-compatible LLM，不允许独立初始化模型。

## Prompt 版本

Agent 的职责、System Prompt、模型、Memory、知识访问、审批与并发配置按不可变版本保存。管理员可创建草稿，并从 AI 员工页进入 Challenger 评测；只有在匹配生产基线的评测通过门禁后才允许发布。旧的直接配置、发布和回滚 API 已弃用，有状态变更时返回 `409` 并写入阻断审计。评测驱动的回滚会创建新的恢复版本而不改写历史，所有动作写入审计日志。

## 路由

- 用户显式 `agent_id`：最高优先级，不存在时返回 404，不静默降级。
- 文本明确提及角色：置信度 0.99。
- 其余消息使用角色专属加权意图词；接近的候选降低置信度并保留原因。
- 无明确意图交给产品经理澄清。
- 已有会话固定 Agent；切换角色要求新会话，避免角色和 Memory 漂移。

## 团队讨论

AI 对齐室的 `TEAM` 会话按产品经理、架构师、测试工程师、运营分析师、项目经理顺序运行。每位员工使用自身已发布 Prompt、模型和并发上限，并读取本轮前序发言；最后一位项目经理输出统一执行方案。每条消息记录实际 `agent_id` 与讨论阶段，供应商 usage 也分别归属对应 Agent。

团队讨论用于方案评审，不推断或执行任何写工具。整轮使用唯一请求 ID 和一次预扣；模型失败、连接取消或上下文失效时通过 `agent_runs` 幂等退款。成功后的最终方案写入项目 Memory，供后续单人对话与工作流读取。

## 工具

8 个默认角色通过 Tool Registry 使用 `context_search`、`knowledge_search`、`task_create`、`requirement_create`、`report_generate`、`notification_create`、`meeting_summary`、`architecture_generate`、`testcase_create`、`analytics_report`。

运行时允许集合 = 代码角色硬白名单 ∩ 数据库启用白名单 ∩ 用户角色。数据库存在配置时，空集合表示全部禁用，不会回退到 Agent 声明。读取项目上下文可自动执行；写任务、报告、通知等工具必须命中明确动作意图。工具名称和资源 ID 写入审计日志，不复制聊天正文。

`knowledge_access=false` 会在运行时移除 `knowledge_search`，不能只靠 Prompt 约束。用户还必须拥有 `agents:read`；涉及项目写入时叠加 `projects:write` 和项目成员角色。

## 人工审批

- 产品经理、项目经理、架构师、会议纪要员和通知秘书默认开启人工确认，可由管理员逐 Agent 调整。
- 当前聊天中的 `task_create` 在执行前写入 `agent_actions`，相同会话和输入复用同一条待审批记录。
- 批准使用数据库行锁；执行前重新检查发起者状态、项目写权限、代码硬白名单和数据库工具权限。
- 已执行或已拒绝动作不能再次决策；审批和拒绝均写入审计日志。

## 并发与幂等

- 每个 Agent 配置 `concurrency_limit`，API 和 StateGraph 节点统一申请执行槽位。
- PostgreSQL/Redis 部署使用带过期时间的 Redis Sorted Set 租约，支持多 Uvicorn 实例；活跃租约会周期续期，异常和断连在 `finally` 释放，进程崩溃由租约过期恢复。
- Redis 不可用时退化到按 Agent 隔离的进程内动态限流器，运行中修改并发上限仍会立即生效；降级模式保持单实例正确性，但不承诺跨实例限流。
- 每次聊天创建唯一 `agent_runs.request_id`，重复请求不会重复推理或扣费。

## 多 Agent 交接与事务边界

- 工作流创建时冻结参与角色的 Prompt、模型和版本；一次运行不会混用不同配置版本。
- 专家节点读取前序节点的真实文档产物，而不是只读取静态占位数据；最终报告汇总完整产物链。
- 只读推理结果进入 `state_json`，有副作用的任务和报告写入必须通过持久化 Saga 步骤执行。
- 回滚由代码注册的补偿器和合法状态机决定，模型不能临时编造撤销动作。
- 终态失败或取消会逆序补偿；补偿对象被人工修改时停止自动处理，锁定该项目的后续工作流并进入人工核对。

## Token 计费

平台采用固定产品额度预扣，同时将供应商返回的 input/output token、模型、耗时和按配置费率估算的成本写入 `llm_usage`。供应商不返回 usage 时明确标记为 `estimated`。余额通过数据库条件 `UPDATE` 原子扣减；执行失败生成唯一退款流水，重复失败回调不会重复退款。

## 反馈与评测

助手消息支持点赞、点踩和保留原回答的重新生成；重新生成不再次执行写工具，并记录原消息关联。管理员可维护跨角色评测用例、必需/禁用证据、Rubric、阈值和权重。每次运行冻结测试集 revision 与 Agent Prompt/模型版本；Challenger 运行会用指定草稿替换目标 Agent 快照，并冻结目标 Agent、候选版本和预期生产版本。异步 worker 按需求覆盖、正确性、相关性、完整性和安全性评分；平均分回退、逐案例回退、Judge 降级或安全失败都会阻断发布。无外部模型时明确使用确定性评分，配置外部 Judge 后若 Judge 失败则不得放行。页面与 `python -m app.evaluation run` 均保留逐案例回答、证据、维度分数、延迟、错误和门禁结论。

团队测试集必须覆盖当前已配置的产品经理、架构师、测试工程师、运营分析师和项目经理核心角色；辅助角色在发布自身 Challenger 时仍必须至少有一个对应角色用例。覆盖契约在运行入队、worker 终态和 Challenger 发布前分别校验，新增核心 Agent 或归档用例不能复用历史绿灯绕过门禁。评测实验室显示权威覆盖状态、缺失角色和补齐入口。

当前仍为点踩的生产回答会进入仅管理员可见的反馈队列；点赞和已改回正向的反馈不会进入。管理员可忽略候选项，或将其转为启用的回归用例。转化事务冻结用户输入、Agent 回答、评论、Agent 身份与角色，后续源消息修改不影响证据；同一反馈最多生成一个用例，`request_id` 保证转化和忽略幂等。审计日志只保存反馈、用例、Agent 和角色标识，不复制输入、回答或评论正文。

发布时再次校验运行已完成、门禁通过、基线与测试集一致、草稿仍匹配冻结证据，并用预期生产版本执行乐观并发检查。发布记录和版本激活在同一事务中写入；`request_id` 保证幂等。回滚只允许作用于仍是当前生产版本的评测发布，创建新的恢复版本并在原发布记录上保留发布者、回滚者、时间和版本链。审计与通知只包含 Agent、运行和版本标识，不包含 Prompt 正文。

## Memory

- 短期：最近 20 条中按 12,000 字符预算截取。
- 用户偏好：Redis。
- 项目：PostgreSQL，普通记忆固定窗口，旧内容合并为每个项目/Agent 唯一滚动摘要，摘要最大 4,000 字符。
