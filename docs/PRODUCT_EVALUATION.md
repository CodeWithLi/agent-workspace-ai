# 产品可用性评估

## 当前结论

平台已经具备中小研发团队内部试用所需的完整主链路：账号与权限、项目协作、Agent 精准选择和意图路由、连续会话、工具审批、真实 StateGraph 多 Agent 协作、任务落库、混合 RAG、版本化评测发布、生产反馈回归闭环、运行追踪、审计与 Python 管理后台。

## 已验证能力

- 显式 Agent 选择优先，角色点名置信度 0.99，会话内固定 Agent，避免角色漂移。
- 短期上下文限额、滚动摘要和项目 Memory 防止记忆无限增长。
- BM25 稀疏召回、embedding 稠密召回、Milvus ANN、融合重排、阈值和引用。
- Agent 请求 ID、运行记录、原子预扣、失败退款、审批行锁、并发租约和长任务续期。
- 同项目工作流互斥、暂停/继续、任务幂等和报告持久化。
- 工作流启动弹窗允许先编辑真实目标，并以零模型调用的只读预检展示四类专业 Agent、目标能力和阻断原因；服务端在扣费、入队和任何需求/产品/架构推理前复核同一就绪政策。
- 动态规划不再依赖一次 Planner 输出：三个隔离视角生成候选，服务端以五项 100 分检查约束能力、角色、成功合同、并行效率和交付防线，架构师在合法候选中仲裁并保留少数意见；候选对比与证据可在计划审批页按版本展开。
- 候选仲裁前由每个实际执行 Agent 独立确认自己的任务合同；项目页按角色展示接受、质疑、弃权、置信度、缺失输入和修改建议。全员接受候选优先，选中方案仍有执行质疑时即使调用方关闭审批也会强制进入人工计划门禁。
- AI 原型把产品经理定义的用户目标编译为绑定真实页面与控件的可执行旅程；用户可在桌面和移动预览中按步骤体验、获得错误反馈并查看进度，批准后自动形成端到端验收用例。
- 失败运行保持不可变，检查点重试使用父子/孙级谱系、请求幂等、项目锁、独立计费与补偿回退产物清理；项目页和追踪中心均可沿深链查看来源运行。
- 运行中的多 Agent 可在节点事务边界安全暂停，操作员原因和恢复指令持久化、幂等、可审计，并作为结构化约束注入后续所有 Agent；追踪中心仅公开干预计数和等待阶段，不泄露指令正文。
- Agent 间只传递必要的结构化状态，报告节点排除重复消息和文档，控制上下文增长。
- 新专业 Handoff 由服务端封存计划、修订、输入、输出和直接上游 SHA-256 指纹；Quality Gate 可确定性阻断被篡改或仍引用旧上游的下游交接，项目页可查看授权范围内的来源链，SSE 不公开完整指纹。
- Quality Gate 由测试、运营和架构三个独立 Reviewer 并行仲裁，使用两份合法合同 quorum、有效评分中位数和多数票，同时保留少数意见；任一开放阻塞项与确定性门禁仍可否决，单 Reviewer 故障不会拖垮已有 quorum，低于 quorum 不会静默放行。
- 运行追踪可按时间、项目和状态分析端到端 P95、Token、预估成本、Agent 延迟与节点瓶颈，并下钻到排队、并行分支、人工等待、模型调用和事件日志。
- 跨运行基线对比可按 Agent 角色和节点/分支定位模型切换后的耗时、Token、成本及结果退化，并支持可分享的深链恢复。
- 可热更新 SLO 覆盖成功率、P95 耗时和单次平均成本，显示错误预算，并用按项目隔离的 MAD 历史基线检测异常运行和直接下钻。
- 异常运行可自动转为持久化告警，支持待确认、处理中、已解决状态，批量确认、解决说明、站内/可选邮件通知和完整审计轨迹。
- 管理员全局汇总与成员本人范围隔离已经验证；追踪只公开运行元数据，不暴露 Prompt、人工反馈、工作流状态正文或产物内容。
- Agent 配置变更必须以 Challenger 草稿进入回归评测；门禁通过且生产版本未漂移才可发布，回滚会创建新的恢复版本并保留完整证据链。
- 团队评测对核心五 Agent 执行角色覆盖硬门禁，并在入队、完成和发布三个事务边界复核；覆盖不足时页面明确列出缺失角色并阻断运行与历史绿灯发布。
- 管理员可一键为缺失核心角色生成可编辑的基础评测套件；生成过程保护已有自定义用例、避免并发重复，并在完成后立即刷新覆盖门禁。
- 当前生产点踩可由管理员人工筛选，冻结为跨角色回归用例后进入后续基线与 Challenger 评测；重复请求、重复转化和审计正文泄露均有自动化测试覆盖。
- 失败评测可驱动 Optimizer/Reviewer 双 Agent 生成受治理的 Prompt 草稿；持久化任务支持续租、fencing、重试和取消，确定性门禁阻断越权与关键词迎合，草稿仍必须经过 Challenger 才能发布。
- Vue 用户工作台与独立 Python 管理后台均可操作核心管理能力。

## 适用范围

适合企业内部需求分析、项目启动、方案评审、任务拆解、测试设计和知识问答。固定 Token 价格用于成本配额和产品验证，不等于供应商实际 token 数；模拟充值不连接支付渠道。

## 上线前外部条件

- 在具有 Docker 的主机完成 PostgreSQL、Redis、Milvus、MinIO 全栈容器验收和备份恢复演练。
- 配置真实 LLM/Embedding 密钥、SMTP、HTTPS、独立强随机 `SECRET_KEY` 和企业管理员邮箱。
- 接入集中日志、指标告警与数据库慢查询监控，并按实际模型账单校准固定 Token 价格。
